Vibepat

Antes de que tu IA invente una solucion desde cero para un problema comun, esto le deja consultar si alguien ya lo resolvio bien.

¿Que es esto?

Para gente que programa con IA

Es para programadores que usan una IA (Claude, ChatGPT, Cursor...) para escribir codigo. Cuando le pides a esa IA algo que ya se ha resuelto bien muchas veces antes, en vez de que se lo invente desde cero en ese momento, esto le da la solucion ya probada para que la use como base.

Si no programas con ayuda de una IA, esto no es para ti todavia — es una herramienta tecnica, no una app de consumo.

El problema

Cada sesion de IA empieza de cero

Cuando le pides a una IA de codigo algo como "monta un chat en tiempo real" o "migra este prototipo a produccion", normalmente improvisa una solucion en esa misma conversacion — y en varias cosas (tiempo real, migraciones, marketplaces) esa solucion improvisada suele ser fragil y hay que rehacerla mas adelante. Este proyecto es una lista de soluciones ya probadas para esos casos concretos.

Como funciona

3 pasos

  1. 1 Conectas el servidor una veza tu herramienta de IA compatible con MCP (ej. Claude Code), con el comando de mas abajo.
  2. 2 Le pides algo normalen tu idioma, como siempre — "quiero un chat con gente conectada en tiempo real".
  3. 3 La IA consulta el registro solasi hay un patron guardado para lo que pediste, lo usa como base en vez de improvisar. No haces nada mas.

Ejemplo real

Que obtienes

Tu: "Quiero montar un chat en tiempo real con estado de presencia (ver quien esta online)"

La IA responde citando el patron guardado: usar un canal de suscripcion sobre Postgres (Supabase Realtime o LISTEN/NOTIFY) para los mensajes, y una tabla de presencia con heartbeat de TTL corto — en vez de montar WebSockets propios gestionados a mano.

Disponibles hoy

7 patrones curados

Chat en tiempo real con presencia

realtime

Postgres/Supabase Realtime + tabla de presencia con heartbeat, en vez de WebSockets propios gestionados a mano.

Migracion de prototipo IA a produccion

migration

Migrar el conocimiento (modelo de datos, flujos validados), no el codigo: reconstruir en capas en vez de reescribir a ciegas.

Marketplace de dos lados

marketplace

Dos roles desde el dia uno, maquina de estados para la transaccion, pagos con Stripe Connect y reputacion bidireccional — en vez de un unico modelo de usuario reescrito a medias.

Auth con multiples proveedores OAuth

auth

Separar "cuenta" e "identidad de login", vinculadas por email verificado — en vez de crear una cuenta nueva cada vez que alguien entra con un proveedor distinto.

Webhooks idempotentes

webhooks

Constraint UNIQUE sobre el id del evento antes de procesar, en la misma transaccion — evita duplicar cobros o emails cuando el proveedor reenvia el mismo evento.

Rate limiting por usuario

api

Token bucket en Redis (no en memoria del proceso) con headers estandar desde el dia uno — no anadirlo despues de lanzar, rompe a clientes existentes.

Paginacion por cursor

database

Keyset pagination (WHERE id > ultimo_id) en vez de OFFSET/LIMIT — evita lentitud y resultados inconsistentes en listados grandes.
